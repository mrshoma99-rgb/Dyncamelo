Filter

Clash.Deduplicate

Keeps ONE clash per unique item pair — the same two elements clashing at five points, or mirrored across an A-vs-B and B-vs-A test matrix, count once. Pairs are unordered and matched by stable item identity (InstanceGuid, else tree path); the first result in input order is the representative, the rest come out on duplicates. 400 raw results, 60 real issues.

InputTypeDefaultWhat it does
results requiredClashResult[]—The clash results — from one test, or several (mirrored A-vs-B / B-vs-A test pairs dedupe too).
OutputType
resultsClashResult[]
duplicatesClashResult[]

Returns: The first result of each unique unordered item pair, and the duplicates that were dropped.

clash deduplicate duplicates unique pair mirror matrix noise merge

Clash.FilterByAngle

Keeps only the clash results whose crossing angle (see ClashResult.Angle) is within a degree range — e.g. 80–90 for near-perpendicular crossings, or 0–10 for parallel runs. Results with no measurable direction are dropped.

InputTypeDefaultWhat it does

minDegreesnumber0.0Lowest crossing angle to keep (0 = parallel).
maxDegreesnumber90.0Highest crossing angle to keep (90 = perpendicular).
OutputTypeWhat it gives
resultsClashResult[]The matching results, input order preserved (angle-less results are dropped).

clash filter angle perpendicular parallel crossing degrees

Clash.FilterByDepth

Keeps clashes whose penetration depth falls in a range, in the unit you name — minDepth 0.025 with units Meters drops every grazing clash shallower than 25 mm, the #1 noise reducer. Depth is positive for overlaps (hard clashes); clearance-test results carry their gap as a NEGATIVE depth, so a range like -1..0 keeps clearance violations instead.

InputTypeDefaultWhat it does
results requiredClashResult[]—The clash results (e.g. from ClashTest.Results).
minDepthnumber0.0Smallest penetration depth to keep. Positive = overlap; clearance-test gaps read as negative depths.
maxDepthnumberPositiveInfinityLargest penetration depth to keep (default: unlimited).
unitsstring"document"Unit of the depth numbers: "document" uses the file's internal unit (often feet!), or name the unit your numbers are in.
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
resultsClashResult[]The matching results, input order preserved.

clash filter depth penetration distance grazing significant units tolerance

Clash.FilterByItemProperty

Keeps clashes whose two items' PROPERTY values match a pair of texts, in either order — the semantic clash rule: category "Element", property "Category", value1 "Pipe", value2 "Wall" keeps pipe-vs-wall clashes whichever side the pipe landed on. An empty value matches anything (one-sided rules). Looks up the property on the item and, by default, its ancestors — clash items are often bare geometry while the data lives on the element above. The geometric sibling is Clash.FilterByOrientation.

InputTypeDefaultWhat it does
results requiredClashResult[]—The clash results (e.g. from ClashTest.Results).
category requiredstring—The property category (tab) name, as the Properties window shows it (e.g. "Element", "Item").
property requiredstring—The property name inside that category (e.g. "Category", "System").
value1 requiredstring—Text one item's property value must match. Empty = any.
value2string""Text the other item's property value must match (either order). Empty = any.
modestring"contains"How the texts must match: contains, equals, starts with or ends with.
searchAncestorsbooleantrueTrue (default) also reads the property from the item's ancestors when the item itself lacks it — clash items are often geometry leaves while the data sits on the element or file above.
caseSensitivebooleanfalseTrue matches exact casing; false (default) ignores case.
OutputTypeWhat it gives
resultsClashResult[]The matching results, input order preserved.

clash filter property category discipline pair pipe wall rule semantic

Clash.FilterByOrientation

Keeps only the clashes between elements of the given box shapes, matched in either order — shape1=run + shape2=wall keeps pipes through walls, run/riser + slab keeps pipes through floors; Clash.FilterByAngle alone cannot tell those apart (both cross at ~90°). Shapes are ClashResult.Orientation's: slab, wall, riser, run, block, or any.

InputTypeDefaultWhat it does
results requiredClashResult[]—The clash results (e.g. from ClashTest.Results).
shape1string"any"Required shape of one element: any, slab, wall, riser, run or block.
shape2string"any"Required shape of the other element (the pair is matched in either order).
OutputTypeWhat it gives
resultsClashResult[]The matching results, input order preserved (results without geometry are dropped).

clash filter orientation wall floor slab pipe shape crossing

Clash.FilterBySet

Keeps clashes whose items belong to a selection/search set (either one, both, or a specific side) — sets are the coordination scope language: "only my package", "only against the existing building". invert turns it into the classic ignore-list: drop every clash touching the "Accepted penetrations" set. An item counts as in the set when itself OR any ancestor is a member, matching how Navisworks selections include descendants.

InputTypeDefaultWhat it does
results requiredClashResult[]—The clash results (e.g. from ClashTest.Results).
set requiredany—The set to test against: a selection/search set, its name, or a list of model items.
whichstring"either"Which items must be in the set: either, both, item1 or item2.
invertbooleanfalseTrue keeps the results that do NOT satisfy the test — the ignore-list mode.
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
resultsClashResult[]The matching results, input order preserved.

clash filter set selection search scope ignore exclude membership

ClashResult.Angle

The angle in degrees (0–90) between the two clashing elements, taken from each element's overall direction (its bounding-box diagonal). ~0° means they run parallel/together, ~90° means they cross perpendicular — so you can filter clashes by crossing angle (e.g. keep only ~90° crossings). Returns NaN when an element has no measurable direction (a point-like box).

InputTypeDefaultWhat it does
result requiredClashResult—The clash result.
OutputTypeWhat it gives
degreesnumberThe angle in degrees (0–90) between the two elements' overall directions.

clash angle degrees perpendicular crossing orientation direction

ClashResult.Orientation

ClashResult.Angle with world context: the crossing angle PLUS each element's bounding-box shape — "slab" (thin horizontal), "wall" (thin upright), "riser" (long vertical), "run" (long horizontal) or "block" — and its slope from horizontal (0–90°). This is what tells a pipe through a wall (run + wall) from a pipe through a floor (run/riser + slab) when the crossing angle alone is 90° in both cases. Box-based: a strongly diagonal linear element can read as planar; "none" means the element has no measurable box.

InputTypeDefaultWhat it does
result requiredClashResult—The clash result.
OutputType
degreesnumber
shape1string
shape2string
slope1number
slope2number

Returns: The crossing angle, each element's box shape (slab/wall/riser/run/block, "none" without geometry) and its slope from horizontal (0–90°).

clash orientation angle wall floor slab pipe shape slope vertical horizontal
