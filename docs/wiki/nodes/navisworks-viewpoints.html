Writing your own nodes

Navisworks: Viewpoints

24 nodes. Every node has its own link: click its name. Types ending in [] are lists; an input with a default is optional.

SavedViewpoint.Apply

Makes a saved viewpoint the current view (camera, plus any saved overrides).

InputTypeDefaultWhat it does
viewpoint requiredSavedViewpoint—The saved viewpoint to apply.
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe applied viewpoint (pass-through).

viewpoint view apply goto camera

SavedViewpoint.ByName

Finds a saved viewpoint by its display name (searches folders too).

InputTypeDefaultWhat it does
name requiredstring—The viewpoint's display name.
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe stored saved viewpoint.

viewpoint view byname find camera

SavedViewpoint.CopyOverrides

Copies the appearance the way one saved view looks — its colour, transparency and hidden-item overrides — onto another saved view, WITHOUT changing that view's camera. Apply one view's highlighting scheme to many others in one graph. Both views must have their overrides baked in (Viewpoint.SaveWithOverrides).

InputTypeDefaultWhat it does
fromViewpoint requiredany—The viewpoint whose colour/transparency/hidden overrides to copy (or its name).
toViewpoint requiredany—The viewpoint to update — keeps its own camera, gains the source's look (or its name).
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe updated target viewpoint.

viewpoint view override appearance copy color transparency hidden apply

SavedViewpoint.Delete

Deletes a saved viewpoint by name (searches folders too). Returns false when absent — safe for clean re-runs of batch generation.

InputTypeDefaultWhat it does
name requiredstring—The viewpoint's display name (folders are searched too).
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
deletedbooleanTrue when a viewpoint was deleted; false when no viewpoint has that name.

viewpoint view delete remove clean

SavedViewpoint.Duplicate

Duplicates a saved viewpoint in its folder, copying its camera and any baked appearance overrides. Names the copy "<name> copy" unless newName is given.

InputTypeDefaultWhat it does
viewpoint requiredany—The saved viewpoint, or its display name.
newNamestringnullName for the copy (null uses "<name> copy").
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe new stored viewpoint copy.

viewpoint view duplicate copy clone

SavedViewpoint.Folder

The folder containing a saved viewpoint: its path as "A/B" ("" for top-level viewpoints) and the folder itself — drives folder-based status workflows.

InputTypeDefaultWhat it does
viewpoint requiredany—The saved viewpoint, or its display name.
documentDocumentnullThe document (defaults to the active document).
OutputType
folderPathstring
folderany

Returns: The folder path ("A/B"; "" at the top level) and the immediate folder (null at the top level).

viewpoint view folder path parent location

SavedViewpoint.Info

Reads a saved viewpoint: its name, folder path ("A/B", "" at the top level), whether it carries a section box, whether it has baked appearance or visibility overrides, its comment count and its camera — the position and the look-at point (one focal distance ahead of the camera, or one unit when none is stored). hasSection reads nothing on Navisworks 2025 and later (it comes back empty).

InputTypeDefaultWhat it does
viewpoint requiredSavedViewpoint—The saved viewpoint.
documentDocumentnullThe document (defaults to the active document).
OutputType
namestring
folderstring
hasSectionboolean
hasOverridesboolean
commentCountinteger
positionPoint
lookAtPoint

Returns: Name, folder path, section / overrides flags, comment count, camera position and look-at point.

viewpoint view info camera folder section overrides comments position lookat

SavedViewpoint.MoveToFolder

documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe moved stored viewpoint (pass-through for chaining).

viewpoint view move folder organize

SavedViewpoint.Update

Re-captures the current view into an existing saved viewpoint — the UI's "Update" — keeping its name, folder and place in the list. Set the camera first (Camera.LookAt, Camera.ZoomToItems, Camera.SetStandardView), then update the view; compare Viewpoint.SaveCurrent, which replaces a view by name with a new one.

InputTypeDefaultWhat it does
viewpoint requiredSavedViewpoint—The saved viewpoint to refresh (or wire it by name through SavedViewpoint.ByName).
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe updated stored viewpoint, still in its folder and position with its name.

viewpoint view update refresh recapture replace camera current

Viewpoint.SaveCurrent

Saves the current view as a new saved viewpoint. An existing top-level viewpoint with the same name is replaced.

InputTypeDefaultWhat it does
name requiredstring—Display name for the new viewpoint.
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe stored saved viewpoint.

viewpoint view save capture camera

Viewpoint.SaveWithOverrides

Saves the current view AND the current temporary color/transparency/hidden overrides into the viewpoint (Navisworks CaptureRuntimeOverrides) — so recalling it restores that exact look, frozen as created. Unlike Viewpoint.SaveCurrent (camera only), each view keeps its own appearance. Use with Appearance.OverrideColorTemporary / OverrideTransparencyTemporary. An existing same-named viewpoint is replaced.

InputTypeDefaultWhat it does
name requiredstring—Display name for the new viewpoint.
folderNamestringnullViewpoint folder to file it under (null/empty stores it at the top level).
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
viewpointSavedViewpointThe stored saved viewpoint.

viewpoint view save overrides appearance capture isolate color freeze

Viewpoint.VisibleItems

Checks which of the given items a viewpoint can see (bounding box vs the camera frustum). Feed it a list of items, a selection/search set, a set name or one item; the viewpoint input accepts a saved viewpoint, a viewpoint name, or nothing for the current view. Note: this is a framing test — items behind other objects still count, and the viewpoint's hide overrides are ignored.

InputTypeDefaultWhat it does
items requiredany—What to test: a list of model items, a single item, a saved selection/search set, or a set name.
viewpointanynullThe viewpoint to test against: a saved viewpoint, a viewpoint name, or empty for the CURRENT view.
fullyInsidebooleanfalseTrue requires an item's whole bounding box inside the view; false (default) counts partly visible items.
documentDocumentnullThe document (defaults to the active document).
OutputType
visibleItemsModelItem[]
outsideItemsModelItem[]
maskboolean[]
containsAnyboolean
reportany

Returns: visibleItems / outsideItems split, a boolean mask over the input order, whether anything is visible, and a diagnostic report.

viewpoint visible contains frustum camera view sees inview mask

OutputTypeWhat it gives

viewpoints clash results batch generate triage

Files

Viewpoints.ExportFile

Exports saved viewpoints — camera, section box and folder location — to a portable JSON package for Viewpoints.ImportFile to rebuild in ANOTHER model, even one in different units. Leave viewpoints empty to export them all, or wire specific viewpoints, folders or names. Element overrides are not carried (they only exist relative to the source model's items).

InputTypeDefaultWhat it does
filePath requiredstring—Where to write the package: a .json file path, or a folder (a dyncamelo-viewpoints.json is created inside). Relative paths land in Documents.
viewpointsanynullWhat to export: nothing = every saved viewpoint; or a viewpoint, a folder, a name (viewpoint first, then folder), or a list of these.
documentDocumentnullThe document (defaults to the active document).
OutputType
filePathfile
countinteger
reportany

Returns: The written file path, how many viewpoints it holds, and a summary report.

viewpoints export transfer copy between models package camera section box

Viewpoints.ImportFile

Rebuilds the viewpoints from a Viewpoints.ExportFile package in THIS model: camera, section box and folder structure. Positions are converted automatically when the source model used different units. Re-runs update same-named views instead of duplicating (overwrite).

InputTypeDefaultWhat it does
filePath requiredstring—The package file written by Viewpoints.ExportFile (or the folder containing its dyncamelo-viewpoints.json).
folderNamestringnullPut every imported view under this folder ("A/B" nests); null/empty recreates each view's original folders.
overwritebooleantrueTrue replaces a same-named viewpoint in the same folder; false always adds.
documentDocumentnullThe document (defaults to the active document).
OutputType
viewpointsViewpoint[]
countinteger
reportany

Returns: The stored viewpoints, how many were imported, and a summary report.

viewpoints import transfer copy between models package restore

Creates a folder in the Saved Viewpoints window, optionally nested under a parent folder. An existing same-named folder in that location is reused, so re-runs are clean.

viewpoints folder create organize nested

Viewpoints.DuplicateFolder

Duplicates a Saved Viewpoints folder — a new folder (created as a sibling) with copies of every viewpoint and nested sub-folder inside. An existing same-named target folder is reused, so re-runs top up rather than pile up.

InputTypeDefaultWhat it does
folder requiredany—The source folder, or its name.
newName requiredstring—Name for the new folder.
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
folderFolderItemThe new stored folder.

viewpoints folder duplicate copy clone organize

Viewpoints.InFolder

All saved viewpoints inside a folder, in Saved Viewpoints window order. Give it a folder object (Viewpoints.CreateFolder / SavedViewpoint.Folder), a folder NAME, or a path like "Reviews/Week 12" to pick between same-named folders; leave it empty for the top level. Nested subfolders are included unless recursive is off. Feeds straight into SavedViewpoint.Apply, Export.ViewpointImage, Viewpoints.ExportFile or a Loop.Item.

InputTypeDefaultWhat it does
folderanynullThe folder to read: a folder object, its name, a path such as "Reviews/Week 12", or empty for the top level of the Saved Viewpoints window.
recursivebooleantrueTrue (default) includes viewpoints in nested subfolders; false lists only the folder's direct children.
documentDocumentnullThe document (defaults to the active document).
OutputType
viewpointsViewpoint[]
namesstring[]
subfoldersany
countinteger

Returns: The viewpoints in tree order, their names, the subfolders met on the way, and how many viewpoints were found.

viewpoints folder contents children list inside views all

Viewpoints.SortFolder

Sorts a Saved Viewpoints folder's contents alphabetically by name (A→Z) — so you never drag-and-drop views into order again. Pass no folder to sort the top level; set recursive to sort nested folders too. Folders sort before/among viewpoints by name.

InputTypeDefaultWhat it does
folderanynullThe folder to sort, or its name; null/empty sorts the top level.
recursivebooleanfalseTrue to also sort every nested folder.
documentDocumentnullThe document (defaults to the active document).
OutputTypeWhat it gives
folderFolderItemThe sorted folder (null when the top level was sorted).

viewpoints folder sort alphabetical order organize arrange
