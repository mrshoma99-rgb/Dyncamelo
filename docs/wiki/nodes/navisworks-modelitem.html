Writing your own nodes

Navisworks: ModelItem

20 nodes. Every node has its own link: click its name. Types ending in [] are lists; an input with a default is optional.

ModelItem.AncestorNameMatches

Walks an item's ancestor chain (nearest first) and tests each name against the text: contains / starts with / ends with, or their "doesn't" negations — true when NO ancestor matches. The branch-membership filter: is this item under the "Steel" branch, inside a file starting with "ARCH-", NOT under anything ending in "-DEMO"? Lace over item lists for the bool mask (List.FilterByBoolMask), and the matching ancestor itself comes out too. Names are matched as the tree shows them (class name when unnamed), case-insensitive unless caseSensitive.

InputTypeDefaultWhat it does
item requiredModelItem—The model item whose ancestor chain to test.
text requiredstring—The text to look for in the ancestor names.
modestring"contains"contains, doesn't contain, starts with, doesn't start with, ends with or doesn't end with. The "doesn't" modes are true when NO ancestor matches.
includeSelfbooleanfalseTrue also tests the item's own name, not just its ancestors'.
caseSensitivebooleanfalseTrue matches exact casing; false (default) ignores case.
OutputType
matchesboolean
ancestorModelItem
ancestorNamestring

Returns: Whether the condition holds, plus the nearest matching ancestor and its name (null/"" when nothing matched — always so for the "doesn't" modes when they hold).

item ancestor name contains starts ends branch under tree hierarchy filter check

ModelItem.AncestorPropertyMatches

The general form of ModelItem.AncestorNameMatches: walks an item's ancestor chain (nearest first) and tests ANY property you name — category + property as the Properties window shows them — against the text: contains / starts with / ends with or their "doesn't" negations (true when NO ancestor matches). "Is this item inside a branch whose Source File contains STEEL?", "under a level whose Name starts with B?" Ancestors without the property simply don't match. Lace over item lists for a List.FilterByBoolMask mask.

InputTypeDefaultWhat it does
item requiredModelItem—The model item whose ancestor chain to test.
category requiredstring—The property category (tab) name, as the Properties window shows it (e.g. "Element", "Item").
property requiredstring—The property name inside that category (e.g. "Name", "Type", "Source File").
text requiredstring—The text to look for in the ancestors' property values.
modestring"contains"contains, doesn't contain, starts with, doesn't start with, ends with or doesn't end with. The "doesn't" modes are true when NO ancestor matches.
includeSelfbooleanfalseTrue also tests the item's own property, not just its ancestors'.
caseSensitivebooleanfalseTrue matches exact casing; false (default) ignores case.
OutputType
matchesboolean
ancestorModelItem
valueany

Returns: Whether the condition holds, plus the nearest matching ancestor and its property value (null/"" when nothing matched — always so for the "doesn't" modes when they hold).

item ancestor property contains starts ends branch under tree hierarchy filter check category

ModelItem.ReferencePoints

Candidate base/reference points of an item, in world document units. Navisworks has NO insertion-point API — bboxCenter/bboxMin come from the bounding box; localOrigin is the item's local-frame origin (COM fragment transform), which approximates the source insertion point for many formats (null when unavailable, e.g. non-geometry items or outside a live session). Source properties (Revit "Location" etc.) remain readable via Properties.Value.

InputTypeDefaultWhat it does
item requiredModelItem—The model item.
OutputType
bboxCenterPoint
bboxMinPoint
localOriginPoint

Returns: Bounding-box center, bounding-box minimum corner, and the local-frame origin (world coordinates; null when the item has no geometry or the value is unavailable).

item reference base point insertion origin location center
